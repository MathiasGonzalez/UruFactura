## ¿Qué es la firma digital en CFE?

DGI exige que cada comprobante fiscal electrónico esté firmado digitalmente con una **firma XML (XML Signature) enveloped**: un nodo `ds:Signature` dentro del CFE, que referencia el documento completo (`URI=""`) con las transformadas *enveloped-signature* y C14N, y que incluye el certificado en `KeyInfo`. Es el mismo formato que usan los ejemplos oficiales de la DGI. Además, **cada mensaje SOAP** se firma con **WS-Security** (el certificado viaja en un `BinarySecurityToken` y se firma el `Body`).

El algoritmo es RSA-SHA256 por defecto; si la DGI rechaza SHA-256 en tu ambiente podés usar `AlgoritmoFirma = AlgoritmoFirma.Sha1`, que es el que usan los ejemplos de la documentación.

UruFactura maneja **toda la complejidad de la firma de forma automática**. Solo necesitás configurar el certificado: la ruta y la contraseña del `.p12`, o un `X509Certificate2` ya cargado.

---

## Certificados soportados

UruFactura acepta certificados digitales en formato:

- **`.p12`** (PKCS#12)
- **`.pfx`** (Personal Information Exchange — equivalente a `.p12` en Windows)

El certificado debe estar emitido por una **Autoridad Certificante reconocida por AGESIC** y vinculado al RUT del emisor.

## Cuándo se firma

`EmitirAsync` firma el CFE al emitirlo; el resultado queda en `emitido.Xml`. Después, `EnviarAsync` arma el sobre `EnvioCFE` (carátula con el certificado + los CFE firmados) y lo envía en un mensaje SOAP firmado con WS-Security al servicio `ws_efactura`. El reporte diario también se firma.

```csharp
var emitido = await client.EmitirAsync(cfe);   // XML firmado en emitido.Xml
await client.EnviarAsync(emitido);             // sobre + WS-Security
```

El código de seguridad que se imprime bajo el QR es el hash (`DigestValue`) de la firma: `emitido.CodigoSeguridad`.

<Aside type="note">
  La DGI exige conservar los XML firmados por al menos **5 años**. Con `UruFactura.EntityFrameworkCore` quedan guardados en la base; si no, guardá `emitido.Xml`.
</Aside>

## Certificado en Azure Key Vault o en un HSM

En lugar de una ruta, podés pasar el certificado ya cargado (con su clave privada, que puede estar en un proveedor remoto). Se usa para firmar los CFE, el reporte, WS-Security y el TLS con la DGI:

```csharp
X509Certificate2 certificado = /* p. ej. CertificateClient.DownloadCertificate(...) de Azure.Security.KeyVault.Certificates */;

var config = new UruFacturaConfig
{
    Emisor      = emisor,
    Certificado = certificado,   // el cliente no lo libera: es tuyo
};
```

## Validar el certificado antes de operar

El cliente carga y verifica el certificado al construirse, así que un problema aparece al iniciar la aplicación:

```csharp
try
{
    using var client = new UruFacturaClient(config);
    Console.WriteLine("✅ Certificado cargado correctamente");
}
catch (FirmaDigitalException ex)   // archivo inexistente, contraseña incorrecta o sin clave privada
{
    Console.Error.WriteLine($"❌ {ex.Message}");
}
```

## Verificar la firma de un CFE

Para verificar un CFE firmado (por ejemplo, uno recibido de un proveedor):

```csharp
bool valida = FirmaDigital.Verificar(xmlFirmado);
```

Comprueba que haya exactamente una firma, hija directa de la raíz, que referencie el documento completo y sea criptográficamente válida (no valida la cadena de confianza del certificado).

## Gestión segura del certificado

<Aside type="caution">
  El archivo `.p12` / `.pfx` y su contraseña son equivalentes a la "firma del escribano". Protegelos con el mismo cuidado que una clave bancaria.
</Aside>

### Recomendaciones de seguridad

1. **No subas el archivo `.p12` al repositorio.** Agregalo a `.gitignore`:
   ```
   *.p12
   *.pfx
   ```

2. **Usá variables de entorno para la contraseña:**
   ```csharp
   PasswordCertificado = Environment.GetEnvironmentVariable("CERT_PASSWORD")!
   ```

3. **En producción, almacená el certificado en un gestor de secretos:**
   - Azure Key Vault (certificados)
   - AWS Secrets Manager
   - HashiCorp Vault

4. **Rotá el certificado antes de su vencimiento.** Los certificados generalmente vencen cada 1 a 3 años.

5. **Usá permisos restrictivos en el archivo del certificado:**
   ```bash
   chmod 600 /ruta/certificado.p12
   chown app:app /ruta/certificado.p12
   ```
