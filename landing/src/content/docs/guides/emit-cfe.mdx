## El modelo: `Cfe` → `CfeEmitido`

- **`Cfe`** describe el comprobante: tipo, receptor, detalle, referencias, etc. Es un record inmutable: se arma con un inicializador y se modifica con `with`.
- **`client.EmitirAsync(cfe)`** lo valida, le asigna el próximo número del CAE vigente, arma el XML, lo firma y lo registra en el almacenamiento (del que sale el reporte diario). No lo envía.
- **`CfeEmitido`** es el resultado: `Numero`, `Serie`, `Cae`, `Totales`, `Xml` firmado, `CodigoSeguridad`, `UrlQr` y el estado ante la DGI (`EstadoDgi`, `AceptadoPorDgi`).

Todos los tipos se crean igual: `new Cfe(TipoCfe.X) { … }`. Ver [Tipos de CFE](../../reference/cfe-types/).

---

## e-Ticket (101)

Para ventas al consumidor final (sin identificar al receptor):

```csharp
var eticket = await client.EmitirAsync(new Cfe(TipoCfe.ETicket)
{
    Detalle =
    [
        new LineaDetalle { NombreItem = "Servicio de consultoría", Cantidad = 2, PrecioUnitario = 3500m, IndFact = IndicadorFacturacion.TasaBasica }, // 22 %
        new LineaDetalle { NombreItem = "Viáticos", Cantidad = 1, PrecioUnitario = 1000m, IndFact = IndicadorFacturacion.Exento },
    ],
});
```

`FechaEmision` es opcional: si se omite, es la fecha de Uruguay al emitir (no la del servidor).

## e-Factura (111)

Requiere identificar al receptor con su RUT:

```csharp
var efactura = await client.EmitirAsync(new Cfe(TipoCfe.EFactura)
{
    Receptor = new Receptor
    {
        Documento   = "214844360018",
        RazonSocial = "Empresa Compradora S.A.",
        Direccion   = "Bulevar España 2345",
        Ciudad      = "Montevideo",
    },
    Detalle = [new LineaDetalle { NombreItem = "Licencia de software anual", Cantidad = 1, PrecioUnitario = 50000m }],
});
```

## Notas de Crédito y Débito

Deben referenciar el CFE original, con su monto y moneda (obligatorios desde el formato CFE v25.01):

```csharp
var notaCredito = await client.EmitirAsync(new Cfe(TipoCfe.NotaCreditoETicket)
{
    Referencias =
    [
        new RefCfe
        {
            TipoCfe      = TipoCfe.ETicket,
            Serie        = "A",
            NroCfe       = 42,                        // número del CFE original
            FechaCfe     = new DateOnly(2025, 6, 15),
            MontoCfeRef  = 1220m,                     // total del CFE original
            MonedaCfeRef = Moneda.PesoUruguayo,       // moneda del CFE original
            Razon        = "Devolución parcial de mercadería",
        },
    ],
    Detalle = [new LineaDetalle { NombreItem = "Devolución - Producto X", Cantidad = 2, PrecioUnitario = 500m }],
});
```

## Validar antes de emitir

`EmitirAsync` valida antes de numerar: un CFE inválido lanza `CfeValidationException` (con la lista en `Errores`) sin consumir números. La validación aplica las restricciones de los XSD de la DGI (largos, montos, fechas, series, caracteres de control) y las reglas del formato, así que lo que la pasa produce un XML válido. Para revisar sin emitir (por ejemplo, en el validador de un endpoint):

```csharp
IReadOnlyList<ErrorValidacion> errores = client.Validar(cfe);
foreach (var error in errores)
    Console.WriteLine($"{error.Campo}: {error.Mensaje}");   // p. ej. "Detalle[0].PrecioUnitario: No puede ser negativo."
```

`Campo` es la ruta de la propiedad dentro del `Cfe`, para mostrar el error junto al dato en un formulario.

## Emitir una sola vez

Si el comprobante corresponde a algo de tu sistema (un pedido, un pago), informá su id en `NroInterno`. Un reintento —por ejemplo, porque el request expiró aunque la emisión se completó— no factura dos veces: `EmitirAsync` lanza `CfeDuplicadoException` con el CFE ya emitido.

```csharp
CfeEmitido emitido;
try
{
    emitido = await client.EmitirAsync(cfe with { NroInterno = pedido.Id });
}
catch (CfeDuplicadoException ex)
{
    emitido = ex.Existente;   // ya estaba emitido
}
```

La regla es por tipo de comprobante (una nota de crédito puede llevar el mismo `NroInterno` que su factura) y no cuenta los CFE que la DGI rechazó: para corregir uno rechazado se emite otro.

## Indicadores de facturación

| Valor | Código | Uso común |
|-------|--------|-----------|
| `IndicadorFacturacion.TasaBasica` | 3 | 22 %: servicios y bienes generales (default) |
| `IndicadorFacturacion.TasaMinima` | 2 | 10 %: alimentos de primera necesidad, medicamentos |
| `IndicadorFacturacion.Exento` | 1 | Bienes y servicios exentos |
| `IndicadorFacturacion.IvaEnSuspenso` | 12 | IVA en suspenso (se informa en `MntIVaenSusp`) |
| `IndicadorFacturacion.OtraTasa` | 4 | Otra tasa o IVA sobre fictos (autos usados, oro): el IVA va en `Cfe.IvaOtraTasa` |
| `IndicadorFacturacion.EntregaGratuita` | 5 | Ítem sin cargo (precio cero), p. ej. la docena de trece |
| `IndicadorFacturacion.NoFacturable` / `NoFacturableNegativo` | 6 / 7 | Conceptos que no se facturan (suman o restan del total a pagar) |
| `IndicadorFacturacion.ExportacionYAsimiladas` | 10 | Exportación y asimiladas (en los tipos de exportación, todas las líneas) |
| `IndicadorFacturacion.ImpuestoPercibido` | 11 | Impuesto percibido |
| `IndicadorFacturacion.IvaMinimoMonotributo` | 16 | Ventas de contribuyentes IVA mínimo o Monotributo (con su CAE especial), sin IVA |
| `IndicadorFacturacion.RebajaRemito` | 8 | e-Remitos: ítem a rebajar de otro remito (con la referencia al remito) |
| `IndicadorFacturacion.AnulacionResguardo` | 9 | e-Resguardo: ítem a anular de otro resguardo (con la referencia) |
| `IndicadorFacturacion.VendedorNoContribuyente` / `VendedorIvaMinimo` / `VendedorImeba` | 13 / 14 / 15 | e-Boleta de entrada: quién vende (14 y 15 con RUT) |
| `IndicadorFacturacion.CompraMonedaExtranjera` | 17 | e-Boleta de entrada: compra de moneda extranjera para reventa |

Los precios son **sin IVA**, salvo con `MontosBrutos = MontosBrutos.IvaIncluido`: el SDK calcula el impuesto y los
totales con la misma precisión que el XML. Los descuentos y recargos globales se aplican a la base de un indicador,
en monto o en `Porcentaje`. Los precios son mayores a cero, salvo en las entregas gratuitas.

Las líneas de e-Tickets, e-Facturas y e-Boletas de entrada pueden documentar retenciones o percepciones (código
numérico de la DGI) con su `AgenteResponsable`: suman al total a pagar (salvo los créditos fiscales, formulario
2181) y en el e-Ticket obligan a identificar al receptor.

## Enviar a la DGI

```csharp
// 1) Sobre: la DGI responde AS (recibido) o BS/BA (rechazado)
var acuse = await client.EnviarAsync(eticket);        // o EnviarAsync([cfe1, cfe2, …]) con hasta 250
if (!acuse.Recibido)
{
    Console.WriteLine($"❌ Sobre rechazado [{acuse.Estado}]: {acuse.Mensaje}");
    return;
}

// 2) Resultado de cada comprobante: Aceptado (AE), Rechazado (BE), Observado (CE)
var estado = await client.ConsultarEnvioAsync(acuse);
foreach (var cfe in acuse.Comprobantes)
    Console.WriteLine($"{cfe}: {cfe.EstadoDgi} {cfe.MensajeDgi}");
```

Tras un reinicio (cuando ya no tenés el acuse), `client.ConsultarCfeAsync(emitido)` consulta un comprobante suelto. Las consultas actualizan el estado en el almacenamiento.

Se envían a la DGI las e-Facturas, e-Remitos, e-Resguardos, e-Boletas de entrada y sus notas, y los e-Tickets con monto neto mayor a 5.000 UI o con retenciones o percepciones; los demás e-Tickets se informan en el reporte diario (enviarlos igual es posible). Un sobre admite hasta 250 CFE y 2 MB. Un CFE que la DGI rechaza queda anulado (`emitido.AnuladoPorRechazo`): se emite otro y, si ya se le había enviado al receptor electrónico, se le comunica con `GenerarNotificacionAnulacionAsync` (ver [Flujos](../workflows/)).

Un CFE que la DGI ya recibió o procesó no se reenvía: `EnviarAsync` lanza `InvalidOperationException`, porque la DGI lo trataría como duplicado (y el estado aceptado quedaría tapado por el rechazo del duplicado). Si el **sobre** fue rechazado (`BS`), sí se reenvía el mismo `CfeEmitido`.

---

## El XML firmado

`emitido.Xml` es el CFE firmado tal como se envía. La DGI exige conservarlo durante el plazo legal:

```csharp
await File.WriteAllTextAsync($"cfe/{emitido.Tipo}_{emitido.Serie}{emitido.Numero:D7}.xml", emitido.Xml);
```

Con `UruFactura.EntityFrameworkCore` ya queda guardado en la tabla `UruFacturaCfes`.

## Manejo de errores

```csharp
try
{
    var emitido = await client.EmitirAsync(cfe);
    var acuse = await client.EnviarAsync(emitido);
}
catch (CfeValidationException ex)        // el CFE no es válido (no se consumió número)
{
    Console.Error.WriteLine(string.Join(Environment.NewLine, ex.Errores));
}
catch (CaeException ex)                  // no hay CAE vigente con números para el tipo
{
    Console.Error.WriteLine(ex.Message);
}
catch (DgiCommunicationException ex)     // red, timeout, SOAP Fault o HTTP sin acuse
{
    Console.Error.WriteLine($"Error de comunicación con la DGI [{ex.CodigoRespuesta}]: {ex.Message}");
}
```

<Aside type="note">
  Si el envío falla por comunicación, el CFE ya está emitido y registrado: no lo vuelvas a emitir (consumiría otro número). Tampoco se sabe si la DGI llegó a recibirlo (un timeout puede ocurrir después de que lo recibió): consultalo con `ConsultarCfeAsync(emitido)` y, si la DGI no lo tiene, reenviá el mismo `CfeEmitido` (o recuperándolo del almacenamiento).
</Aside>

Ver [Códigos de respuesta DGI](../../reference/dgi-codes/) para la lista completa de estados.
